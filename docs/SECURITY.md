# Security

The declared dependency set pins bcrypt 4.0.1 for Passlib 1.7.4 compatibility. The clean validation environment was rebuilt with bcrypt 4.0.1; startup and authentication passed without the version-detection warning. The legacy backend/venv remains stale and may still emit the old warning if used.

Bearer JWTs protect case routes. Investigators access owned cases; supervisors/admins review cases. Unknown and unauthorized IDs return 404 to reduce enumeration. Production requires a non-default secret and PostgreSQL. Login failures are throttled in-process (five failures per source IP per 60 seconds); production should move this control to a shared gateway/store. CORS is restricted to the configured local frontend origins, and provider/LLM credentials remain backend-only. Evidence links are validated against the requested case, and unsupported AI identity/off-case/future-fact requests are refused before a configured LLM is called. Key case lifecycle actions—case creation/view, investigation completion, evidence save, and report generation—are persisted in AuditLog records. The current Passlib 1.7.4 / bcrypt 4.2.1 pairing emits a non-fatal startup version-detection warning; exercised authentication remains reliable, but the dependency pairing should be cleaned up during the next environment rebuild. No live provider or PostgreSQL runtime has been verified in this pass.
